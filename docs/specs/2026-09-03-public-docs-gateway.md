# Public Docs Gateway 스펙

- 날짜: 2026-09-03
- 상태: 구현됨
- 관련 결정: [ADR 008](../adr/008-public-docs-gateway.md)

## 목표

- GitHub Pages에서 nohdol-study 문서를 읽기 좋은 정적 사이트로 제공한다.
- 첫 화면에서 주제를 선택하고, 주제별 문서 목록·전체 검색·본문 읽기로 이동할 수 있게 한다.
- 공개할 문서를 명시적으로 선택하여 개인 vault와 설치 정보의 우발적 노출을 막는다.

## 비목표

- `vault/`의 학습 노트를 자동 게시하는 기능
- 인증이 필요한 비공개 문서 호스팅
- Markdown 정본을 사이트 전용 복사본으로 이관하는 작업
- 로컬 `_workspace` 포털을 대체하는 작업

## 요구사항

### R1. 게이트웨이와 주제 탐색

첫 화면은 사이트 목적, 전체 문서 검색, 주제 카드를 제공한다. 주제를 선택하면 설명과 권장 문서 순서가 나타나고, 언제든 게이트웨이로 돌아올 수 있다.

### R2. 문서 읽기

문서는 제목·요약·예상 읽기 시간·원본 경로를 표시한다. Markdown의 제목, 목록, 표, 코드, 인용, 링크를 읽기 좋은 HTML로 렌더링하며 모바일 한 열 레이아웃을 지원한다.

### R3. 검색과 깊은 링크

제목·요약·본문을 한 번에 검색한다. 주제와 문서는 URL hash로 직접 열 수 있고 브라우저 뒤로 가기가 동작한다.

### R4. 공개 범위 게이트

카탈로그 경로는 저장소 내부의 Git 추적 Markdown이어야 한다. 절대 경로, `..`, 중복 ID, 존재하지 않는 파일, `vault/`, `REGISTRY.md`, `_workspace/`를 빌드 실패로 처리한다. 빌드 과정은 vault 심링크를 순회하지 않는다.

### R5. 재현 가능한 정적 빌드

Node.js 22에서 잠금 파일로 의존성을 설치하고 `docs-site/dist/`를 만든다. 사이트의 URL과 asset은 프로젝트 Pages 하위 경로에서도 동작하는 상대 URL이어야 한다.

### R6. Pages 배포

`main`의 공개 문서·사이트 변경과 수동 실행에 반응하는 GitHub Actions workflow가 테스트와 빌드를 거쳐 Pages artifact를 배포한다. 배포 job은 `pages: write`와 `id-token: write`만 추가로 사용한다.

### R7. 직접 전달

완료하고 새로 검증한 일반 변경은 별도 승인 단계 없이 commit하여 `origin/main`에 push한다. workflow 성공과 공개 URL의 HTTP 응답을 확인한다. force push·히스토리 재작성·파괴적 Git 작업·릴리스·시크릿·다른 원격이나 브랜치는 범위 밖이다.

## 완료 기준

- 카탈로그의 모든 문서가 빌드 결과에 포함되고 게이트웨이의 주제 수·문서 수와 일치한다.
- 검색 데이터에 제목·요약·본문 텍스트가 있고 비공개 경로 문자열이 소스 경로로 포함되지 않는다.
- 카탈로그 문서 사이의 상대 Markdown 링크가 사이트 내부 문서 링크로 바뀐다.
- 잘못된 경로, 미추적 파일, 중복 ID를 결정적 테스트가 거부한다.
- 로컬 HTTP 서버에서 게이트웨이, 주제, 문서, 검색, 모바일 레이아웃을 확인한다.
- 전체 하네스 검증이 통과한다.
- push 뒤 Pages workflow가 성공하고 공개 URL이 HTTP 200을 반환한다.
