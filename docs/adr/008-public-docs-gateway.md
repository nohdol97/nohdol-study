# ADR 008 — 공개 문서는 명시적 카탈로그를 거쳐 GitHub Pages에 배포한다

- 날짜: 2026-09-03
- 상태: 활성
- 대상: `docs-site/`, `.github/workflows/docs-pages.yml`, `AGENTS.md` 7절
- 관련 스펙: [Public Docs Gateway](../specs/2026-09-03-public-docs-gateway.md)

## 맥락

저장소의 `docs/`는 ADR·스펙·가이드를 보관하지만 브라우저에서 학습 순서를 고르기 어렵다. 별도의 로컬 `_workspace` 포털은 반복 이용하는 개인용 사이트를 모으는 표면이며 인터넷 배포를 목표로 하지 않는다. 실제 지식 루트인 `vault/`는 개인정보와 비공개 학습 자료를 포함할 수 있고 Git에서 제외되어 있으므로 GitHub Actions가 읽거나 공개 문서에 자동 포함해서는 안 된다.

## 결정

공개 문서 사이트의 소스는 `docs-site/`에 둔다. 사용자가 처음 만나는 페이지는 주제 카드가 있는 게이트웨이며, 주제 안에서 문서를 고르거나 전체 본문을 검색할 수 있다.

- 공개 대상은 `docs-site/catalog.json`에 저장소 상대 경로로 명시한다.
- 빌드는 Git이 추적하는 Markdown만 허용하고 `vault/`, `REGISTRY.md`, `_workspace/`와 경로 이탈을 거부한다.
- 기존 `docs/`, 루트 안내서, 예제 README를 정본으로 두며 사이트는 빌드 시 HTML과 검색 텍스트를 만든다.
- 생성된 `docs-site/dist/`는 추적하지 않고 GitHub Actions의 Pages artifact로만 전달한다.
- `_workspace` 포털은 로컬 다이내믹 사이트, `docs-site`는 인터넷에 공개하는 추적 문서라는 경계를 유지한다.
- 문서 본문은 근거가 아니라 기존 추적 문서의 표현 표면이다. 내용의 사실성·검증 상태는 원본 문서 계약을 따른다.

## 배포 운영

이 저장소는 완료하고 새로 검증한 일반 변경을 별도 확인 없이 commit하여 `origin/main`에 push해도 된다는 사용자 상시 승인을 갖는다. Pages workflow까지 성공하고 공개 URL이 응답해야 배포가 완료된 것이다. force push, 히스토리 재작성, 파괴적 Git 작업, 릴리스, 시크릿, 다른 원격·브랜치는 이 승인에 포함하지 않는다.

## 왜 vault 자동 스캔이 아닌가

Pages 배포는 공개 동작이다. 디렉터리 스캔은 새 노트가 생겼다는 이유만으로 공개 범위를 넓히며, Git에서 제외한 지식 루트 경계를 무력화한다. 명시적 카탈로그는 공개 의도를 코드 리뷰 가능한 한 줄로 만든다.

## 왜 `docs/`를 애플리케이션 루트로 바꾸지 않는가

`docs/`는 의사결정 기록의 안정된 경로이며 저장소 안 링크가 이미 이 구조를 사용한다. 앱 소스와 의사결정 문서를 섞으면 Pages 자산, 패키지 파일, ADR이 같은 탐색 계층에 놓인다. `docs-site/`가 기존 Markdown을 읽게 하면 정본을 복제하지 않고 UI만 독립적으로 발전시킬 수 있다.

## 결과

- 저장소 방문자는 게이트웨이에서 관심 주제를 먼저 고를 수 있다.
- 공개 범위가 카탈로그와 Git 추적 상태로 이중 제한된다.
- 로컬 vault 없이도 CI에서 같은 사이트를 만들 수 있다.
- 새 공개 문서는 파일 작성과 카탈로그 등록을 함께 해야 발견된다.
