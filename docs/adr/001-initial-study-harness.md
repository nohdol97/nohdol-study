# ADR 001 — 파일 기반 공부 하네스 Phase 1 구조

- 날짜: 2026-07-25
- 상태: 활성
- 대상: 저장소 골격, 설치 레지스트리, vault 연결, 지식 규약, Claude Code·Codex 훅

## 결정

| 결정 | 내용 | 이유 |
|---|---|---|
| 지식과 하네스 분리 | 하네스만 Git으로 추적하고 `vault` 심링크와 `REGISTRY.md`는 미추적 | 컴퓨터마다 지식 위치·내용·동기화 방식이 다르다 |
| 선택 경로가 지식 루트 | 설치 시 선택한 디렉터리에 `raw/`, `wiki/`, 인덱스·로그·핫 캐시를 직접 생성 | 기존 vault 루트와 전용 하위 폴더를 같은 모델로 지원한다 |
| Obsidian 선택 사항 | `.obsidian`이 없어도 설치하고 Markdown 규약을 그대로 사용 | 그래프 UI가 없어도 하네스 핵심은 파일 조작만으로 동작해야 한다 |
| 기존 자료 무변경 | 설치기는 없는 항목만 만들고 레거시 노트는 마이그레이션하지 않는다 | 기존 245개 노트 등 사용자 자산의 오염과 데이터 손실을 막는다 |
| Markdown이 원본 | 위키링크가 관계의 원본이며 DB와 시각화는 파생물 | 도구 중립성과 장기 이식성을 유지한다 |
| 공용 스킬 원본 | `.agents/skills`만 편집하고 Claude는 심링크, Codex는 네이티브 발견을 사용 | 두 CLI의 워크플로 드리프트를 막는다 |
| 공용 훅 스크립트 | CLI별 설정은 같은 SessionStart·Stop 셸 스크립트를 호출 | 등록 형식만 분리하고 동작은 한곳에서 관리한다 |
| 자동 도구 설치 없음 | Phase 1 설치기는 상태만 기록하며 Obsidian·향후 CLI를 설치하지 않는다 | 설치처 정책과 네트워크·권한을 함부로 변경하지 않는다 |
| vault Git은 로컬 정책 | 감지 결과만 레지스트리에 기록하고 `git init`은 하지 않는다 | Google Drive, Obsidian Sync, 별도 Git 등 선택이 설치처마다 다르다 |
| 정확성은 주장 단위로 검증 | 1차 출처 우선, 중요 주장 교차검증, 반증·불확실성·확인일 기록 | 그럴듯한 오정보가 지식 자산으로 굳는 것을 막는다 |
| AI 출력은 근거가 아님 | Claude·Codex·Gemini·NotebookLM 결과는 탐색·분석 보조로만 사용 | 모델 간 합의는 독립 관측이 아니며 같은 오류를 공유할 수 있다 |

## 결과

각 컴퓨터에서 선택한 실제 경로·프로필·동기화 방식은 공용 ADR이 아니라 미추적 `REGISTRY.md`에만 남는다.

Phase 2는 웹·논문·영상 ingest가 실제 필요해질 때 별도 스펙과 검증을 거쳐 추가한다. 그래프 인덱스는 노트가 충분히 쌓인 뒤 실측한다.
