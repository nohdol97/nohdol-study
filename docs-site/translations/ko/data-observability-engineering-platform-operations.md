# 플랫폼 운영: 릴리스·복구·용량·비용

파이프라인을 만든 엔지니어가 자리를 비운 사이 장애가 났다. 동료가 기록된 절차만으로 원인을 찾고 데이터셋을 복구할 수 있을까?

이 장에서는 그 복구를 반복할 수 있게 만든다. 학습 시스템에 필요한 만큼 배포 자동화, 격리, 처리 용량을 추가하고 유효한 작업에 드는 비용을 확인한다.

## 이 장에서 처음 쓰는 말

| 용어 | 의미 | 왜 필요한가요 · 언제 쓰나요 |
|---|---|---|
| RPO | Recovery Point Objective, 복구 시점을 기준으로 허용하는 데이터·진척 손실량 | 얼마나 최근의 진행 상태를 잃어도 되는지에 따라 백업·복제 요구를 정한다. **구체적인 상황(가상 예시):** 복구 요구가 진행 상태 5분의 유실을 허용한다. → 백업·복제의 복구 지점을 조사한다. → 실제 복구 가능한 지점이 한도를 만족하는지 확인한다. |
| RTO | Recovery Time Objective, 합의한 서비스 결과를 복원하는 목표 시간 | 허용할 최대 중단 시간에 맞는 복구 방식을 선택하고 연습할 때 쓴다. **구체적인 상황(가상 예시):** 서비스가 30분 안에 복구돼야 한다. → 탐지·복원·검증을 하나의 시간표로 연습한다. → 측정한 전체 시간을 RTO와 비교한다. |
| 카나리(canary) | 변경을 제한된 범위에 먼저 적용하고 관찰한 뒤 더 많은 사용자나 데이터로 확대하는 방식이다. | 기존 기준과 새 릴리스 결과를 비교하는 동안 위험에 노출되는 범위를 제한한다. **구체적인 상황(가상 예시):** 파이프라인 배포가 모든 소비자의 파생 데이터를 망가뜨릴 수 있다. → 중단 기준을 정하고 대표성 있는 제한 범위에 먼저 적용한다. → 범위를 넓히기 전에 정확성과 운영 신호를 비교한다. |
| 역압(backpressure) | 뒤쪽 시스템이 처리 속도를 따라가지 못할 때 앞쪽 작업의 속도를 늦추는 것이다. | 과부하된 하위 단계 때문에 상위 대기열·낭비 작업이 끝없이 늘어나는 것을 막는다. **구체적인 상황(가상 예시):** 후속 저장소가 처리하는 속도보다 이벤트가 빨리 들어온다. → 버퍼 크기를 제한하고 지원되는 상류 흐름 제어를 적용한다. → 메모리가 제한되고 과부하 처리 정책이 드러나는지 확인한다. |
| 워크로드 신원(workload identity) | 실행 중인 서비스나 작업이 권한을 요청할 때 사용하는 신원이다. | 영구 사용자 비밀을 코드에 넣지 않고 실행 서비스에 제한된 권한과 추적 가능한 행위를 부여한다. **구체적인 상황(가상 예시):** 정기 잡이 장기 키를 코드에 넣지 않고 저장소에 접근해야 한다. → 실행 신원에 좁은 범위의 권한을 연결한다. → 토큰 획득·허용 동작·무관한 접근 거부를 시험한다. |
| 단위 비용(unit cost) | 관련 총비용을 성공적으로 끝낸 작업의 유효한 단위 수로 나눈 값이다. | 유효하게 성공한 출력당 관련 비용 전체를 기준으로 운영 설계를 비교한다. **구체적인 상황(가상 예시):** 플랫폼 총비용이 늘었지만 효율이 나빠졌는지 알 수 없다. → 의미 있는 작업 단위로 귀속 비용을 나눈다. → 처리량·서비스 품질과 함께 성공 단위당 비용을 비교한다. |

## 먼저 이해하기

1. 앱 코드·스키마·계약·인프라·관측성 설정을 버전 관리한다.
2. 격리 예제로 호환성·정확성을 검증한다.
3. 제한된 환경이나 워크로드 일부에 배포한다.
4. 사용자 결과·용량을 관찰해 확대하거나 멈춘다.
5. 롤백 중 데이터 상태를 대사하고 릴리스 근거를 유지한다.

컨테이너는 런타임을 묶지만 영속 체크포인트 위치를 정의하지 않는다. Kubernetes는 워크로드·자원을 관리하지만 앱 출력에 트랜잭션을 주지 않는다. Terraform은 선언 인프라를 관리하지만 테이블 백업 복원을 입증하지 않는다. 이 책임이 생기면 기존 [Kubernetes 로드맵](../../content/kubernetes/00-roadmap.md)과 [Terraform 로드맵](../../content/terraform-aws/00-roadmap.md)을 보조 과정으로 쓴다.

## 코드와 데이터 계약을 함께 배포하기

| 변경 | 호환성 질문 |
|---|---|
| 필드 추가 | 이전 리더는 무시하고 새 리더는 과거 부재를 처리하는가? |
| 이름·타입 변경 | 공존 기간과 시험한 소비자 전환이 있는가? |
| 단위·업무 규칙 변경 | 물리 스키마가 같아도 의미 버전이 보이는가? |
| 스트리밍 상태 연산자 변경 | 선택 엔진이 기존 체크포인트를 안전하게 복원하는가? |
| 테이블 프로토콜 기능 활성화 | 모든 필수 리더·라이터가 계속 읽고 커밋하는가? |

필요하면 확장 후 축소를 쓴다. 호환 표현을 추가·채우고 비교한 뒤 사용자를 옮기고 관찰 후 이전 표현을 제거한다. 코드 롤백이 바뀐 업무 규칙으로 이미 공개된 결과를 자동 취소하지 않는다. 코드 롤백·데이터 수정·사용자 재공개를 명시적 작업으로 둔다.

CI는 스키마·예제를 확인하고 작은 결정적 정확성 예제를 실행하며 증분·전체 결과와 허용·거부 경계를 비교해야 한다. 큰 처리량 검사는 별도로 환경을 기록한다. 단위 테스트 통과는 용량 벤치마크가 아니다.

## 복구는 테이블 파일보다 넓다

Kafka·소스 재생 보존, DB 로그, 테이블 메타데이터·오브젝트, 카탈로그, 스트림 체크포인트, 오케스트레이션 메타데이터, 스키마 레지스트리, 정책, 텔레메트리·계보 보존을 조사한다. 서로 사용 가능한 복구 시점을 고른다. 가용 입력보다 앞선 체크포인트나 비호환 출력 상태를 가리키는 체크포인트는 복구 실패·잘못된 출력을 만들 수 있다.

격리 목적지에서 복원을 연습한다. 카탈로그·테이블, 호환 처리 상태를 복원하거나 의도적으로 재생하고 검사 후 소비자 신원으로 질의한다. 사고 시작부터 합의한 사용자 결과까지 재며 백업 다운로드 시간만으로 RTO를 삼지 않는다.

복구 중 근거를 조용히 지우지 말고 정책대로 원시 소스를 보존한다. 전체 재생이 불가능한 때와 재구성 소스를 문서화한다. 필요한 이력이 사라졌다면 재시작 성공을 완전 복구라 하지 말고 데이터 공백을 밝힌다.

## 용량과 비용을 함께 보기

유입 평균 10 MB/s에서 한 시간 멈추면 복제·오버헤드 전 십진 단위 적체는 36 GB다. 유입 10 MB/s를 계속 받으며 다음 한 시간에 비우려면 그 기간 평균 유효 처리율이 최소 20 MB/s여야 한다. 읽기만 빨라져 병목을 옮기지 않도록 출력 처리량도 측정한다.

큐 나이, 저장 여유, 소스 보존, 하위 동시성을 함께 본다. 역압이 무제한 메모리 축적을 막으려면 상위에 영속 대기 장소와 가득 찼을 때 정책이 있어야 한다. 자동 확장은 외부 API 제한·인기 파티션을 없애지 않는다.

**유효하게 공개된 이벤트** 100만 개당 비용, 갱신 구간당 비용, 성공한 AI 과제당 비용처럼 단위를 정한다. 유휴 계산, 재시도, 스캔, 병합, 저장, 전송, 텔레메트리, 품질 검사, 거버넌스를 포함한다. 시도 이벤트당 낮은 비용은 데이터 삭제나 품질 실패를 숨길 수 있다.

## 데이터 경로의 Docker·Kubernetes·Terraform

컨테이너 이미지는 변환 런타임을 재현해야 한다. 검토한 기본 이미지·의존성을 고정하고 CI와 같은 모듈, 의도한 사용자, 배포 환경 설정을 사용한다. 변하는 노트북 상태·미기록 패키지는 목적을 깨뜨린다. 자격 증명은 이미지·빌드 컨텍스트 밖에 두고 체크포인트·출력은 컨테이너 임시 쓰기 계층이 아닌 영속 위치에 둔다.

Kubernetes requests는 스케줄링, limits는 플랫폼 규칙에 따른 사용 가능 자원에 영향을 준다. Spark 실행기에는 힙 외·네이티브·Python 워커 메모리도 필요하므로 JVM 힙만으로 Pod 예산을 정할 수 없다. 정상적으로 오래 걸리는 배치를 재시작하는 liveness는 무한 재생을 만들 수 있다. readiness는 트래픽 수신 가능성이지 어제 데이터 완전성이 아니다.

워크로드 신원은 해당 소스·출력·체크포인트·텔레메트리에 필요한 권한만 가져야 한다. 네트워크 정책과 저장 권한은 다른 경계를 강제한다. 실제 신원으로 금지 데이터셋 읽기를 시험해 거부를 기록한다. 큰 과거 백필이 현재 공개 용량을 전부 쓰지 않도록 자원도 격리한다.

Terraform은 설정·계획으로 인프라 변경을 검토 가능하게 한다. 버킷·역할 생성 plan은 행 수준 업무 계약을 검증하지 않는다. 상태·provider 자격 증명에 적절한 저장·접근을 적용한다. 인프라 롤백과 이미 바뀐 데이터셋 복원을 구분한다. 해당 경계에 도달하면 기존 인프라 과정의 전체 컨테이너·오케스트레이션·IaC 실습을 이용한다.

## 릴리스 묶음과 승격 결정

코드 리비전, 런타임·의존성, 소스·스키마·계약, 테이블 기능, 변환 정의, 정책, 텔레메트리 스키마를 묶어 승격한다. 기준 입력에는 중복, 충돌 갱신, NULL, 늦은 수정, 삭제, 구간 누락, 비허용 호출자를 넣는다. 전체·증분 출력은 수·합계뿐 아니라 키·값으로 비교한다.

제한 구간이나 shadow 목적지에 후보를 실행하고 승인 버전과 소비자 쿼리를 비교한다. 검사 통과 전 후보를 격리한다. 통화·이력 규칙이 바뀌면 코드 롤백 뒤에도 새 의미의 행·AI 인덱스가 남을 수 있어 릴리스 설계에 수정·재공개를 포함한다.

필수 불변식 전부 통과, 금지 읽기 없음, 현재 구간 기한 충족, 측정 따라잡기 용량이 요구율 초과처럼 승격 조건을 명시한다. 쉬운 키만 본 카나리는 쏠린 키·늦은 갱신 동작을 입증하지 못한다. 대표 구간을 의도적으로 고른다.

## 복구 계산: 재생 예산과 병목

적체 `B`, 유입률 `lambda`, 유효 처리율 `mu`에서 `mu > lambda`이면 일정 속도 배출 시간은 `B / (mu-lambda)`다. `mu <= lambda`이면 적체를 비울 수 없다. 이벤트, 인코딩 바이트, 복제 바이트, 압축 Parquet 바이트는 다르므로 단위를 일관되게 쓴다.

소스 이력 6시간, 탐지 2시간, 복원 1시간, 따라잡기 예상 2시간이면 모델대로 보존·위치가 동작할 때 가장 오래된 입력 만료까지 변동 여유가 1시간뿐이다. 체크포인트 나이, 소스 시계, 테이블 복구 시점도 포함한다. 계산 증설은 소스·네트워크·키 분포·출력이 추가 처리량을 공급·사용할 수 있을 때만 도움된다.

플랫폼은 백필 승인 제어, 제한 재시도, 소스 보존 알람, 데이터셋별 공개 근거를 제공해야 한다. 영구 스키마 오류를 반복하면 계산만 소모하고 결과는 그대로 나쁘다. 재시도 가능한 전송·용량 실패와 무효 입력·비호환 계약을 분류한다.

## 단위 경제성과 셀프서비스 경계

분자·분모에 같은 기간을 써 유효 공개 이벤트 100만 개당 비용을 구한다. 수집·변환·실패 재시도·병합·저장·전송·질의 제공·텔레메트리·필수 검사를 포함한다. 대상 절반을 버린 설계는 겉보기 처리량·비용 비교 전에 완전성 관문에서 실패해야 한다.

셀프서비스 데이터셋 등록은 파이프라인 설정, 품질 규칙, 소유권, 대시보드, 접근 정책 요청을 생성할 수 있다. 등록 스키마에 행 단위, 소스·변경 ID, 신선도·완전성 모집단, 보존, 담당자, 허용 사용자를 필수로 두고 검증·컴파일해 검토 가능한 산출물로 만든다. YAML의 `certified: true`가 실행 검사·담당자 승인을 대신해서는 안 된다.

생성 플랫폼 산출물은 등록·템플릿에서 나온 버전 있는 파생물로 취급한다. 템플릿 변경 시 영향 데이터셋을 보여 주고 대표 예제를 시험하며 점진 배포한다. 작동하는 파이프라인 하나에서 여러 팀용 플랫폼으로 넘어가는 운영 연결이다.

## 운영자의 사고 대응 순서

영향받는 사용자·시간 구간부터 시작한다. 관측 범위, 마지막 유효 공개, 실행·계보 참조를 따라 상위로 간다. 원인 후보와 반증을 찾고 해로운 공개·부하를 억제한 뒤 근본 조건 수정, 제한 구간 재생, 예상 출력 대사를 한다. 복구 후 알림·임시 정책을 복원한다.

사후 기록에 시간선, 영향 데이터셋·사용자, 실제 원인 근거, 기여 조건, 복구 조치, 남은 공백, 회귀 예제를 넣는다. 빨강 패널 뒤 녹색 패널 화면만으로는 대부분을 잃는다.

## 실행 결과 예시

공급자 벤치마크·가격 견적이 아닌 용량 계산 워크시트다.

```text
incoming rate: 100 events/s
recovery processing rate: 300 events/s
backlog: 360000 events
net drain rate: 200 events/s
drain estimate: 1800 seconds
processing rate <= incoming rate: backlog cannot drain
```

복구 창이 20분인데 배출이 30분이면 재시작 성공이어도 실패다. 보존·하위 병목을 확인하고 유휴·저장·전송·복구 요금을 포함해 승인 공개 비용을 보고한다.
