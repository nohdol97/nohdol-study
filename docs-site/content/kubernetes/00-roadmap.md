# 쿠버네티스 전체 학습 로드맵

이 과정의 목표는 쿠버네티스 리소스 이름을 외우는 것이 아니다. 사용자가 선언한 상태가 API에 저장되고, 여러 컨트롤러가 현재 상태를 관찰해 원하는 상태로 조정하는 흐름을 이해한 뒤, 애플리케이션 배포와 장애 대응에 적용하는 것이 목표다.

> 현재는 **목차 단계**다. 각 장은 앞으로 사용자가 지정한 공식 문서 링크를 기준으로 상세 설명, 다이어그램, YAML 예시, 명령 실행 흐름, 실패 사례와 연습 문제를 추가한다.

## 링크 한 개를 학습 문서로 확장하는 방식

앞으로 링크를 받을 때마다 해당 장에 다음 요소를 추가한다.

1. **한 문장 모델** — 이 기능이 해결하는 문제와 책임을 먼저 적는다.
2. **관계 다이어그램** — 요청·데이터·제어 흐름 중 이해에 필요한 구조를 그린다.
3. **최소 실행 예시** — 작은 YAML과 `kubectl` 명령으로 정상 경로를 재현한다.
4. **상세 해설** — 각 필드와 컴포넌트가 왜 필요한지 연결한다.
5. **실패 예시** — 흔한 오해, 이벤트·상태·오류 메시지와 복구 순서를 보여준다.
6. **운영 판단** — 개발 환경과 프로덕션 환경에서 달라지는 선택을 구분한다.
7. **근거와 확인일** — 공식 페이지와 버전을 기록하고 번역 지연 여부를 확인한다.
8. **복습 질문** — 명령을 외우지 않고 원리를 재구성할 수 있는 질문을 남긴다.

## 현재 범위

- 포함: 공식 Kubernetes 핵심 개념, 기본 실습, 운영과 확장으로 이어지는 학습 경로
- 이후 추가: 사용자가 제공하는 개별 링크의 깊이 있는 설명과 다이어그램
- 제외: 개인 vault 노트의 자동 공개, 검증하지 않은 블로그 복사, 특정 클라우드 사업자에 종속된 운영법
